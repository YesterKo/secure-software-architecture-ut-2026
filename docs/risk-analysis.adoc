= Risk Analysis

== Attack resistance analysis

=== Spoofing

* **Applicable:** Login through TARA but after that we use browser sessions
* **Attack:** Someone steals session cookie through XSS or tricks user into approving something else
* **Countermeasures:** Shorter session lifetime, secure cookies, CSP, check for XSS. Maybe Smart-ID signing for more important actions

=== Tampering

* **Applicable:** Data between portal, KVKR, TIS etc, also documents and audit logs
* **Attack:** Changing requests or data, SQL injection, path traversal, malicious uploads. Admin messing with audit logs
* **Countermeasures:** HTTPS, X-tee, secure internal communication too. Input validation, parameterized queries, upload limits, antivirus. Restrict audit log access

=== Repudiation

* **Applicable:** Citizens submit requests, staff make decisions, admins change settings
* **Attack:** User says they never submitted something, staff denies making a decision. Admin/DevOps changing settings without a trace.
* **Countermeasures:** Audit who did what and when, protect logs from editing. How long to keep logs? Could have different retention for different events. Log config/deployment changes, signing for important actions

=== Information Disclosure

* **Applicable:** Sensitive health and defence data in the portal
* **Attack:** Access someone else's data through API, intercept traffic, leak data through logs or URLs
* **Countermeasures:** Check permissions on every resource request, HTTPS/X-tee, no personal IDs in URLs, avoid sensitive data in logs and notifications

=== Denial of Service

* **Applicable:** Public portal/backend, especially when lots of people log in around call-ups
* **Attack:** Spam API requests, fill storage with uploads/logs, too many requests to KVKR/TIS (could even DoS them ourselves)
* **Countermeasures:** Rate limiting, upload limits, Cloudflare or similar? Monitoring, autoscaling maybe. Limit retries/requests to external services

=== Elevation of Privilege

* **Applicable:** Different permissions for citizens, delegates, staff and admins
* **Attack:** Vulnerable library leading to RCE, stolen admin session, bypass role checks, changing admin flag in DB
* **Countermeasures:** Keep libraries updated, backend permission checks. Who can give admin rights? Re-authentication for important admin actions, regular backups
