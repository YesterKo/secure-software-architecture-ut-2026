== Quality Attribute Scenarios

[cols="2,3,8"]
|===
3+s|Scenario for QAS-001

2+s|Scenario(s)
|TIS unavailable during health-related workflow

2+s|Business Goals
|Trusted single entry point; easier conscription and health-assessment workflows

2+s|Relevant Quality Attributes
|Availability; Reliability & Fault Tolerance; Interoperability

.6+^.^s|Scenario Components
s|Stimulus
|TIS becomes unavailable while a citizen is using a workflow that requires health information.

s|Stimulus Source
|Health Information System (TIS)

s|Environment
|Normal portal operation; KVKR and other portal functionality remain available.

s|Artifact
|Health-related portal workflow and TIS integration.

s|Response
|The affected operation returns an unavailable or pending state. Already accepted citizen data is preserved and unrelated workflows remain usable.

s|Response Measure
|The citizen receives an explicit unavailable or pending state within 5 seconds. No accepted request is lost or duplicated, and unrelated workflows remain usable.

2+s|Questions
|Can the affected operation continue asynchronously, or must the citizen retry it later?

2+s|Issues
|The exact behavior depends on which health information is required and whether the workflow can proceed without an immediate TIS response.
|===


[cols="2,3,8"]
|===
3+s|Scenario for QAS-002

2+s|Scenario(s)
|Unauthorized access to protected data

2+s|Business Goals
|Protect citizens' rights and public trust by ensuring that identity, health, and defence-related personal data are handled responsibly and lawfully.

2+s|Relevant Quality Attributes
|Security & Privacy; Auditability

.6+^.^s|Scenario Components
s|Stimulus
|An authenticated user attempts to access health, defence-obligation, case, or document data without the required authorization.

s|Stimulus Source
|Authenticated citizen or agency staff member.

s|Environment
|Normal portal operation.

s|Artifact
|Authorization handling and protected-data access.

s|Response
|Access is denied, no protected data is returned, and the attempt is recorded for audit.

s|Response Measure
|All requests in the defined unauthorized-access test set are denied, no protected data is returned, and an audit record is created within 5 seconds.

2+s|Questions
|Which roles and service-specific rules determine access to KRA, Defence Forces, and health-related data?

2+s|Issues
|Authorization may depend on information owned by external organizations, so the source and freshness of permissions must still be defined.
|===


[cols="2,3,8"]
|===
3+s|Scenario for QAS-003

2+s|Scenario(s)
|TIS interface changes

2+s|Business Goals
|Improve cooperation between KRA, the Defence Forces, and health-information systems; reduce the long-term cost and effort required to operate, maintain, and extend the portal and its integrations.

2+s|Relevant Quality Attributes
|Maintainability; Interoperability

.6+^.^s|Scenario Components
s|Stimulus
|TIS introduces a new supported interface version or changes the structure of exchanged health data.

s|Stimulus Source
|Health Information System (TIS).

s|Environment
|The portal is already integrated with KVKR, TIS, and Defence Forces systems.

s|Artifact
|TIS integration and directly dependent portal functionality.

s|Response
|The TIS integration is updated without requiring changes to unrelated external integrations or portal functionality.

s|Response Measure
|Contract tests for the updated TIS interface pass, and regression tests for the KVKR and Defence Forces integrations continue to pass without changes to their interface contracts.

2+s|Questions
|How long must older external interface versions remain supported?

2+s|Issues
|The actual versioning and compatibility guarantees provided by TIS are not yet known.
|===


[cols="2,3,8"]
|===
3+s|Scenario for QAS-004

2+s|Scenario(s)
|Peak demand during a call-up period

2+s|Business Goals
|Provide citizens with one trusted digital entry point for selected national-defence services; make conscription, health-assessment, and reserve-service workflows easier to access and complete.

2+s|Relevant Quality Attributes
|Performance; Scalability; Availability

.6+^.^s|Scenario Components
s|Stimulus
|Portal traffic increases to five times the normal test load during a conscription call-up period or large reserve-service notification.

s|Stimulus Source
|A large number of citizens accessing the portal within the same period.

s|Environment
|Peak operation while KVKR, TIS, and Defence Forces systems remain available.

s|Artifact
|Citizen-facing portal and core portal-owned workflows.

s|Response
|The portal increases processing capacity and continues serving users without widespread errors or loss of accepted requests.

s|Response Measure
|At five times normal test load, at least 95% of common interactive requests complete within 3 seconds, the error rate remains below 1%, and no successfully accepted request is lost.

2+s|Questions
|What request rate and number of concurrent users represent normal and realistic peak usage?

2+s|Issues
|Normal and peak workload baselines are not yet known, so the five-times-load target must be validated once realistic traffic estimates are available.
|===
